# Schools Picker — Cascading DepEd Data Design

## Goal

Replace the hardcoded 97-school flat list in onboarding with a cascading Region → Province → City → School picker backed by ~6,000 DepEd-sourced schools stored in Supabase and cached locally in SQLite.

## Architecture

A one-time Node.js scraper seeds a `schools` Supabase table. The mobile app fetches school data lazily by region and caches each region's schools in a SQLite table. The UI is a single persistent bottom-sheet modal with breadcrumb navigation. No changes to the `userSettings` schema — the school field continues to store a plain name string.

## Tech Stack

- **Scraper**: Node.js + `node-fetch` + `cheerio` (HTML) or `xlsx` (Excel), whichever the DepEd page serves
- **Supabase**: `schools` table, public SELECT RLS, seeded via SQL migration
- **SQLite cache**: Drizzle `schoolsCache` table, one row per region, 30-day TTL
- **Hook**: `useSchoolPicker.ts` — all fetch/cache logic
- **Component**: `SchoolPicker.tsx` — breadcrumb modal UI
- **Integration**: `onboarding.tsx` swaps current school block for `<SchoolPicker />`

## Section 1: Data Pipeline

### Scraper — `scripts/scrape-schools.js`

Fetches `https://www.deped.gov.ph/k-to-12/senior-high-school/list-of-senior-high-schools/`. The DepEd page may link to a downloadable Excel/CSV file or render an HTML table.

**Strategy:**
1. Fetch the page HTML
2. If an `.xlsx` or `.csv` download link is found, download and parse with `xlsx`
3. Otherwise, parse the HTML table with `cheerio`
4. For each row, extract: `region`, `division` (maps to `province`), `city/municipality`, `school name`, `school ID`
5. Normalise region names to the standard 17-region set (see table below)
6. Write output to `scripts/schools-data.json`

**DepEd Division → Province mapping rule:** DepEd "Divisions" are either province-level (e.g., "Ilocos Norte") or standalone-city-level (e.g., "Division of Cebu City"). Map standalone city divisions to their parent province for the `province` column; use the city name as `city`. Province divisions use the division name as `province`; individual rows carry the `city` field.

**Standard region names (normalise all variants to these):**
```
NCR, Region I, Region II, Region III, Region IV-A, Region IV-B (MIMAROPA),
Region V, Region VI, Region VII, Region VIII, Region IX, Region X,
Region XI, Region XII, Region XIII (Caraga), CAR, BARMM
```

**Output shape per entry:**
```json
{
  "region": "NCR",
  "province": "Metro Manila",
  "city": "Quezon City",
  "name": "Quezon City Science High School",
  "deped_id": "300093"
}
```

The scraper outputs two files:
- `scripts/schools-data.json` — full dataset for review and re-seeding
- `supabase/migrations/008_schools.sql` — CREATE TABLE DDL + all INSERT statements embedded directly; self-contained, requires no external files at run time

### Supabase Migration — `supabase/migrations/008_schools.sql`

```sql
CREATE TABLE IF NOT EXISTS schools (
  id SERIAL PRIMARY KEY,
  region TEXT NOT NULL,
  province TEXT NOT NULL,
  city TEXT NOT NULL,
  name TEXT NOT NULL,
  deped_id TEXT
);

CREATE INDEX schools_region_idx ON schools(region);
CREATE INDEX schools_province_idx ON schools(province);
CREATE INDEX schools_city_idx ON schools(city);

-- Row-level security: public read, no write from client
ALTER TABLE schools ENABLE ROW LEVEL SECURITY;
CREATE POLICY "schools_public_read" ON schools FOR SELECT USING (true);
```

INSERT statements are generated by the scraper and written directly into the migration file. The migration is idempotent (`ON CONFLICT DO NOTHING`).

## Section 2: Local SQLite Cache

### Schema addition — `apps/mobile/db/schema.ts`

```typescript
export const schoolsCache = sqliteTable('schools_cache', {
  region: text('region').primaryKey(),
  data: text('data').notNull(),       // JSON: SchoolEntry[]
  cachedAt: integer('cached_at').notNull(),
})
```

### Cache behaviour

- **Key**: region string (e.g., `"NCR"`)
- **TTL**: 30 days (`Date.now() - cachedAt > 30 * 24 * 60 * 60 * 1000`)
- **On miss**: fetch `SELECT * FROM schools WHERE region = $1` from Supabase, write full result as JSON to `data`
- **On hit**: parse `data` JSON directly, no network call
- **On offline miss**: fetch fails → show "Can't load schools, check your connection" toast + reveal freetext input

### Type

```typescript
export interface SchoolEntry {
  region: string
  province: string
  city: string
  name: string
}
```

## Section 3: Hook — `apps/mobile/hooks/useSchoolPicker.ts`

```typescript
interface SchoolPickerState {
  level: 'region' | 'province' | 'city' | 'school'
  selectedRegion: string | null
  selectedProvince: string | null
  selectedCity: string | null
  list: string[]          // current level's items
  loading: boolean
  error: string | null
  selectRegion: (r: string) => void
  selectProvince: (p: string) => void
  selectCity: (c: string) => void
  goBack: () => void      // pops one breadcrumb level
  reset: () => void
}
```

**Derived lists:**
- `regions`: distinct sorted region values from cached data (fetch all regions list once from Supabase — cheap, ~17 rows)
- `provinces`: derived from cached region data once region selected
- `cities`: derived from cached region data once province selected
- `schools`: derived from cached region data once city selected

The hook loads the regions list on mount. Provincial/city/school lists are computed in-memory from the cached JSON — no additional Supabase calls after the region is cached.

## Section 4: Component — `apps/mobile/components/SchoolPicker.tsx`

### Props

```typescript
interface SchoolPickerProps {
  value: string           // current school name string
  onChange: (school: string) => void
}
```

### Layout

**Trigger row** (rendered in onboarding form):
- Same `TouchableOpacity` style as current school field
- Shows selected school name or placeholder "Search your school..."

**Modal** (full-height bottom sheet, same dark panel style as current modal):
- **Header**: `"Select your school"` title
- **Breadcrumb row**: `Region › Province › City › School` — each completed segment is tappable (color `#fca5a5`), pending segments are dimmed
- **Search input**: `autoFocus` on first open, clears when level changes, filters current list
- **FlatList**: current level's items with `›` chevron for region/province/city; checkmark for school
- **"Others" footer** (school level only): `"Others — type my school name"` in `rgba(252,165,165,0.8)` — sets `isOthers=true`, modal closes, freetext input appears below trigger row (same as current behaviour)

### State machine

```
region list → [tap region] → province list → [tap province] → city list → [tap city] → school list
     ↑              ↑                ↑                ↑
   goBack         goBack           goBack           goBack
```

`goBack()` pops one level: from school → city, city → province, province → region. Tapping a breadcrumb segment jumps directly to that level.

### Loading states

- Spinner shown while fetching region cache from Supabase
- Error state shows inline message + freetext fallback

## Section 6: Error Handling

| Scenario | Behaviour |
|---|---|
| No internet, region not cached | Toast: "Can't load schools. Check your connection." + freetext input shown |
| Supabase fetch fails (non-network) | Same as above, error logged |
| Empty city (no schools in DepEd data) | Show "No schools found for this city" + Others option |
| User selects Others | Freetext input, any string accepted |
